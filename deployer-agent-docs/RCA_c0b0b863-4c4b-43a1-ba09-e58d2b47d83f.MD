# RCA — Deploy run c0b0b863-4c4b-43a1-ba09-e58d2b47d83f (adam-nn-demo)

## Symptom
Initial deploy failed at the `build_image` step (Cloud Build step #39, `backend-build 13/13`) during `pip install -r /app/backend/requirements.txt`.

## Root cause
`backend/requirements.txt` line 130 pins:

```
torch==2.15.0+cpu
```

The `+cpu` suffix is a PyTorch *local version* wheel that is published **only** on PyTorch's own index (`https://download.pytorch.org/whl/cpu`), **not** on default PyPI, which is the index the build uses. pip therefore fails:

```
ERROR: Could not find a version that satisfies the requirement torch==2.15.0+cpu
  (from versions: 2.0.0, ... 2.14.1, 2.15.0)
ERROR: No matching distribution found for torch==2.15.0+cpu
```

Note PyPI *does* offer plain `torch==2.15.0` — only the `+cpu` local variant is missing.

## Evidence
- Build error excerpt (above) from the failed run's `error_message`.
- Source confirmed in eph sandbox: `grep -n torch /app/scratch/backend/requirements.txt` → `130:torch==2.15.0+cpu`.
- Fix verified in eph sandbox: `pip install 'torch==2.15.0' --no-deps --dry-run` → `Would install torch-2.15.0` (resolves cleanly from default PyPI).

## Fix (Code — E1)
Edit `backend/requirements.txt` line 130:

```
- torch==2.15.0+cpu
+ torch==2.15.0
```

On linux the default-PyPI `torch==2.15.0` wheel is already a CPU build, so no GPU/CUDA payload is pulled in. After this change, redeploy.

(An alternative — adding `--extra-index-url https://download.pytorch.org/whl/cpu` to the install — was rejected: it masks a bad source pin with a manifest hack and is unnecessary since plain `torch==2.15.0` satisfies the requirement.)
